-need Design.md to be up to date after each change
-read the spec before deciding how to code this

-should replicate most of the features of the 'yousician' application
-allow playing of various songs in various keys with various instruments
	-default acoustic guitar for starters
-shows the oncoming 'stream' of notes and how to play them like in yousician
	-however needs to show 'killfeed' grading quality of each note
	-rather than ending the song when it goes horrible there should be a 'healthbar' that goes up and down, once failed can keep playing but it won't count as a pass
-need assorted variations of wide variety of public domain
-need instrument tuning utilities
	-need detection of when out of tune
-need indication of when to use guitar capo
-need ability to manually create songs
-need ability to create songs by having the app 'listen' to something and then break it down into songs with different levels of complexity for different instruments
	-can also 'watch and listen' and then song background can be a slideshow of what showed in a designated rectangle.
	-or created songs can have some generic background that shows behind the notes (provide some animated and solid colour backgrounds)
-need ability to import/export/view file location of song files
-need trending of improvement in each instrument over time
	-need a whole training plan and course progression for each instrument
	-need various drills of variable difficulty and length for grinding week skills
-need a whole music lore/glossary/dictionary reference section
-need a suite of minigames for developing quizzing music theory
-need option to play the underlying song at customizable volume when playing
-need option to include vocal track with songs (which can be optionally played alongside at its own volume)
-need different views of history, session history, etc.
-graphics should be very clean and crisp throughout
-needs to be constantly clear what input and output devices are used
-need to be able to select various themes
-need an isolated Docker build/run: build + verification suite + the static
	server all execute inside the container, no host Node/npm install required
-need option to slow down (and speed up) song playback for practice, without
	changing pitch — affects the backing/vocal audio, the synthesized band, the
	note highway timing, and grading windows together, not just visual scroll
-need an optional "strict" practice mode (checkbox toggle) in Play: a missed
	or fumbled note rewinds the song to just before it and repeats it until
	played correctly, with no health/score penalty for the failed attempts —
	only a clean pass finalizes and counts
	-the rewind must be short (back up one note, not several seconds)
	-don't replay music that was already played correctly — freeze exactly on
	 the missed note and wait there (nothing plays) until it's hit right, then
	 ease back up to normal speed rather than snapping straight to it
-need a settings option for how fretboard strings are labelled: note names
	(E A D G B e) or numbers (1-6)
-need a way to resize the fretboard/fingering display from the Play controls
-need the ability to pick an arbitrary segment of a song myself and loop it
	for practice, not just play the whole song top to bottom
	-selection should be a visible timeline I can drag on, like a video editor
	 (Sony Vegas etc), not just "mark start/end at the current position"
-need a guided "Learn this song" mode: the song is split into segments, and I
	practice each one at a slow speed, gradually speeding it up as I get it
	right, before moving to the next segment
	-Learn mode should be its own separate component (not wedged into the Play
	 view's code) so it can keep growing on its own
	-Learn mode uses the same timeline, showing segment boundaries + which one
	 is active
